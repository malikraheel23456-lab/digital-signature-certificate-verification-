# Digital Signature and Certificate Verification System

**Selected course artifact:**  Digital Signature and Certificate Verification System  
**Implementation:** Python, Streamlit, `cryptography`, RSA-PSS, SHA-256

## 1. Project overview
This project creates a classroom prototype for digitally signing documents and verifying whether the document has changed. It also includes a simulated trusted-key directory record so a verifier can compare a public key with a recorded key fingerprint and status.

## 2. Features
- Generate an RSA-2048 public/private key pair.
- Create a simulated trusted-key record with owner label, key ID, SHA-256 fingerprint and ACTIVE status.
- Sign the exact bytes of a document using RSA-PSS with SHA-256.
- Verify a document/signature/public-key combination.
- Detect a modified document, modified signature or unrelated public key.
- Check whether the supplied public key matches an ACTIVE classroom trust record.
- Download generated keys, signature and trust record.
- Analytics dashboard with live counts and charts based on actual app activity.
- SQLite activity history for signing and verification attempts.
- Download activity history as CSV.
- Download an individual verification report as PDF.

## 3. Requirements
- Windows 10/11
- Python 3.10 or newer
- VS Code (recommended)

## 4. Installation on Windows
Open the project folder in VS Code. Open Terminal and run:

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If `py` is not recognized, try `python` instead.

## 5. Run the application

```powershell
streamlit run app.py
```

The application opens in your browser. If it does not open automatically, use the local URL printed in the terminal (normally `http://localhost:8501`).

## 6. New dashboard and reporting features
- **Dashboard:** displays total activities, signed documents, verification attempts, valid signatures, invalid signatures and trusted-key matches.
- **Charts:** automatically update from records saved by this application. Charts are empty until you sign or verify documents.
- **Activity History:** stores timestamp, action, filename and verification metadata in `verification_history.db`.
- **CSV export:** download the activity history for analysis.
- **PDF report:** after a verification attempt, download a report containing the result and public-key fingerprint.
- The local database does not store document contents, private keys or signature bytes.

## 7. Demonstration workflow
1. Open **Generate Keys & Trust Record**.
2. Enter a signer label such as `BZU Examination Office`.
3. Generate the RSA key pair.
4. Download `private_key.pem`, `public_key.pem` and `trusted_key_record.json`.
5. Open **Sign a Document** and upload a sample PDF/TXT plus `private_key.pem`.
6. Download the generated `.sig` file.
7. Open **Verify a Document** and upload the same document, `.sig`, `public_key.pem` and `trusted_key_record.json`.
8. Confirm that signature status is VALID and simulated key trust is TRUSTED.
9. For tampering test, edit the document (even one character), save it under a new name and verify again. The signature should be INVALID.
10. For wrong-key test, generate a second key pair and upload its public key. Verification should be INVALID.

## 10. Security and academic limitations
- RSA-PSS is used for signatures; RSA encryption padding is not used because this project is about signing, not encrypting.
- SHA-256 is used as the message digest within RSA-PSS.
- The private key generated by this classroom application is unencrypted for ease of demonstration. Store it securely and do not share it. A production system should use encrypted key storage and stronger operational controls.
- The trust record is a simulated local directory entry, not an X.509 certificate, certificate chain, revocation service or real certificate authority.
- A valid signature establishes that the corresponding private key signed the exact bytes being verified. Real-world identity and authorization require reliable key enrollment and governance.
- Use only synthetic or authorized test documents.

## 11. Brief RSA-PSS and ElGamal signature comparison
RSA-PSS is the implemented scheme. It uses RSA keys and randomized padding for signatures. ElGamal signatures are based on discrete-logarithm assumptions and require different parameters and signing/verification procedures. Their security assumptions and parameter choices differ; they are not interchangeable. This prototype implements RSA-PSS only.
